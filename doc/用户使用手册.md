## 1. 产品简介

### 1.1 系统定位

**医院虚拟会诊系统（Virtual Consultation System, VCS）** 是一套基于多智能体协作（Multi-Agent）的桌面端**临床决策支持系统（CDSS）**。

> ⚠️ **重要声明**：本系统是**辅助决策工具**，不替代执业医师的诊断与治疗决策。所有 AI 生成的会诊意见均需经主治医师审核确认后方可执行。

### 1.2 核心能力

| 能力 | 说明 |
|------|------|
| 病历自动整合 | 从 HIS/EMR/LIS/PACS 多个医院信息系统抽取并标准化患者数据 |
| 多智能体协作会诊 | 模拟呼吸内科、心内科、神经内科、内分泌科、影像科、药学 6 大专科 AI 专家进行联合诊断 |
| 循证医学支持 | 每条诊疗建议标注循证等级（A/B/C/D）和推荐强度（强推荐/弱推荐/有条件推荐） |
| 医学知识图谱 | 基于症状-疾病-检查-药物关联网络支持鉴别诊断 |
| 全流程闭环 | 会诊申请 → 执行 → 报告生成 → 审核确认 → 归档 |

### 1.3 专科 AI 专家列表

| 智能体 ID | 名称 | 专长 |
|-----------|------|------|
| pulmonology_v1 | 呼吸内科 AI 专家 | COPD、肺炎、肺栓塞、肺部占位 |
| cardiology_v1 | 心内科 AI 专家 | 冠心病、心力衰竭、高血压、急性冠脉综合征 |
| neurology_v1 | 神经内科 AI 专家 | 脑血管疾病、眩晕综合征 |
| endocrinology_v1 | 内分泌科 AI 专家 | 糖尿病、代谢综合征 |
| radiology_v1 | 影像科 AI 专家 | 影像报告解读、占位鉴别 |
| pharmacy_v1 | 药学 AI 专家 | 用药安全审核、药物相互作用 |

## 2. 系统要求与安装

### 2.1 系统要求

**桌面版（推荐使用打包后的 exe）**：
- 操作系统：Windows 10/11（64 位）
- 硬盘空间：≥ 300 MB
- 内存：≥ 4 GB
- 无需安装 Python 环境

**开发者版（从源码运行）**：
- Python 3.10+
- 见 `requirements.txt` 列出的依赖

### 2.2 安装方式一：使用打包后的可执行程序（推荐）

1. 获取发布包（`医院虚拟会诊系统.zip` 或解压后的 `医院虚拟会诊系统/` 目录）
2. 解压到任意位置，例如 `D:\Apps\医院虚拟会诊系统\`
3. **首次运行**：双击目录中的 `医院虚拟会诊系统.exe`
4. Windows SmartScreen 可能提示"未知发布者"，点击"更多信息"→"仍要运行"即可
5. 程序启动后即出现主界面，无需任何配置

> 📁 **注意**：请保持发布目录的完整性，不要单独拷贝 `exe` 文件，否则程序将无法找到所需的依赖与数据文件。

### 2.3 安装方式二：从源码运行（开发者）

```bash
# 1. 克隆/解压源码
cd MultiAgentHospital

# 2. 安装依赖
pip install -r requirements.txt

# 3. 下载测试数据集（可选，用于真实数据演示）
python scripts/download_datasets.py

# 4. 启动桌面应用
python main.py
```

### 2.4 自行打包

```bash
# 使用打包脚本（包含测试、构建、验证步骤）
python scripts/build_exe.py

# 或直接调用 PyInstaller
pyinstaller build.spec --clean --noconfirm
```

打包完成后，产物位于 `dist/医院虚拟会诊系统/`。

## 3. 快速开始（5分钟上手）

### 3.1 启动与登录

双击 `医院虚拟会诊系统.exe`，首先出现**登录窗口**。

系统内置三个默认账户（首次启动自动创建）：

| 用户名 | 默认密码 | 角色 | 用途 |
|--------|----------|------|------|
| admin | admin123 | 管理员 | 系统维护、用户权限管理、全局审计（不参与临床诊疗） |
| doctor | doctor123 | 医生 | 患者管理、发起会诊、生成报告、提交审核 |
| reviewer | reviewer123 | 审核员 | 审核工作台、会诊报告只读查看与审核确认、审核记录 |

> ⚠️ **安全提示**：首次登录后请立即通过"修改密码"功能更改默认密码（详见第 4 章）。

登录窗口功能：
- 输入用户名和密码，点击"登录"或按回车
- 勾选"记住用户名"可在下次启动时自动回填
- 连续 5 次密码错误将锁定 30 秒，防止暴力破解
- 登录成功/失败均写入审计日志

### 3.2 工作台主界面

登录成功后进入工作台，界面分为三部分：

- **顶部头部栏**：显示当前用户（姓名/角色/科室），提供"修改密码"与"退出登录"
- **左侧导航栏**：按角色清晰划分功能模块
- **右侧内容区**：随导航切换的功能页面

**三类角色导航项完全不同，实现职责隔离：**

| 导航项 | 医生 | 审核员 | 管理员 |
|--------|:----:|:------:|:------:|
| 📊 工作台首页 | ✓ | ✓ | ✓（系统概览） |
| 👥 患者管理 | ✓ | — | — |
| 🩺 虚拟会诊 | ✓ | — | — |
| 📝 会诊报告（含"提交审核"） | ✓ | ✓（只读 + "审核确认"） | — |
| 🗂️ 我的工作空间 | ✓ | — | — |
| 🩺 审核工作台 | — | ✓ | — |
| 🗂️ 审核记录 | — | ✓ | — |
| ⚙️ 系统管理 | — | — | ✓ |

> 🔒 登录不同角色看到的功能完全不同：管理员仅维护系统信息；医生负责临床诊疗全流程并提交审核；审核员负责审核工作台、报告审核与审核记录，三者导航互不重叠。会诊报告页的"提交审核"按钮仅医生可见，"审核确认"按钮仅审核员可见。

### 3.3 加载示例患者

进入"患者管理"页面，点击 **"加载示例病例"**。系统自动从 HIS/EMR/LIS/PACS 适配器整合病历。

左侧"示例患者列表"会显示：
```
ZY20260728001 | 李建国 | 呼吸内科
ZY20260731002 | 王秀兰 | 心内科
```

点击列表中的患者可切换查看，中间区域展示患者全景视图。

### 3.4 查看患者全景

在"患者管理"页中间的患者全景视图中，可以看到：

- **基本信息**：患者 ID、姓名、性别、年龄、科室、主管医生、住院号
- **病历文本**：主诉、现病史、既往史
- **检验结果**：列表展示所有检验项，异常项以黄色背景标注
- **影像报告**：CT/X 线等影像检查的发现与印象
- **医学影像图片**：上传的 DICOM/JPG/PNG/BMP 等医学影像附件缩略图与预览
- **用药记录**：当前用药的药品、剂量、频次、状态
- **NLP 实体提取**：自动从病历文本中提取症状与疾病关键词

### 3.5 发起一次会诊

1. 切换到"虚拟会诊"导航
2. 填写"临床问题"（例如："胸痛原因待查"）
3. 选择"会诊类型"（MDT/常规/急诊）和"优先级"
4. 选择参与的专家：
   - 点击 **"智能推荐"** 让系统根据病情自动选择
   - 或点击 **"全选"** 召集所有 6 个专科
   - 或手动勾选需要的专科
5. 点击 **"开始虚拟会诊"**

会诊执行期间会显示进度对话框（通常 1-3 秒完成）。**完成后报告会自动持久化到您的个人用户空间**，并在审计日志中记录。

### 3.6 查看会诊报告

会诊完成后，程序自动切换到"会诊报告"页面。

报告包含：
- **报告基本信息**：会诊编号、患者、类型、状态、生成时间
- **鉴别诊断表**：按置信度排序的诊断列表，含证据等级与支持专科数
- **推荐检查**：去重合并后的检查项目清单
- **治疗方案**：循证推荐的治疗策略
- **用药建议**：药学 Agent 提出的用药安全提示
- **风险评估**：各专科风险判断汇总
- **随访计划**：标准化的随访建议
- **不确定性声明**：当诊断置信度不足或鉴别诊断较多时主动提示
- **最终结论**：综合多学科 AI 专家意见的最终判断

### 3.7 保存与导出报告

- 点击 **"保存为 JSON"** 或 **"保存为 Markdown"** 将报告导出到本地（医生、审核员均可导出）

### 3.8 医生提交审核

医生完成会诊后，需将会诊报告提交给审核员审核（**仅医生可见"提交审核"按钮**）：

1. 在"会诊报告"页点击橙色 **"提交审核"** 按钮
2. 确认提交对话框中核对会诊编号与患者信息后点击"是"
3. 报告状态变为 `PENDING_REVIEW`，并自动进入审核队列（`data/review_queue/queue.json`）
4. 审核员即可在"审核工作台"看到该待审核报告
5. 提交操作写入审计日志（`SUBMIT_FOR_REVIEW`）

> 📌 防重复提交：同一会诊编号仅能存在一条队列记录。被驳回的报告可重新提交（状态自动恢复为 `PENDING`）。医生也可撤回尚未审核的提交。

### 3.9 审核员工作台

审核员登录后拥有独立的工作空间（与医生空间完全不同），由三个模块组成：

**① 审核工作台**（🩺 审核工作台）—— 审核员的核心工作界面：
- 列表展示所有医生提交的待审核报告（会诊编号、患者、类型、申请医生、科室、优先级、提交时间）
- 选中一行后可：
  - **查看报告详情**：跨用户加载医生空间的报告并展示（只读）
  - **审核通过**：弹出审核对话框（可填审核意见），通过后报告状态变为 `APPROVED` 并回写医生空间，记录审计日志（`APPROVE_REPORT`）
  - **驳回**：弹出驳回对话框（必填驳回原因），驳回后报告状态变为 `REJECTED` 退回给医生，记录审计日志（`REJECT_REPORT`），医生可修改后重新提交

**② 会诊报告**（📝 会诊报告）—— 只读查看报告，仅审核员可见 **"审核确认"** 按钮（与审核工作台的通过功能互补）：
- 审核确认后报告状态变为 `APPROVED` 并归档
- 审核操作写入审计日志（`APPROVE_REPORT`）

**③ 审核记录**（🗂️ 审核记录）—— 审核员个人历史审计台账：
- 列表展示该审核员已处理的所有报告（会诊编号、患者、类型、申请医生、审核结果、审核人、审核时间、审核意见）
- 支持查看选中报告详情（跨用户加载）
- 数据来源为审核队列中 `reviewer_id` 等于当前审核员的记录

**审核员首页仪表盘**展示审核队列统计：待审核报告数、已审核报告数、已驳回报告数；最近动态展示待审核与最近审核记录。

> 🔒 审核员无法访问患者管理、虚拟会诊、我的工作空间，专注于报告审核职责；审核操作通过 `GlobalConsultationIndex.update_report_status()` 跨用户回写医生空间报告状态，确保医生侧同步看到审核结果。

### 3.10 我的工作空间

切换到"🗂️ 我的工作空间"页面（**仅医生可见**），可查看您个人空间持久化的所有会诊记录（与他人数据隔离）：

- 表格列出会诊编号、患者、类型、状态（含 `PENDING_REVIEW`/`APPROVED`/`REJECTED`）、创建/完成时间
- 支持查看选中报告（跳转至"会诊报告"页，可在该页导出 JSON/Markdown 或提交审核）、删除选中报告
- 患者数据也可在"患者管理"页右侧"我的患者空间"单独管理

## 4. 用户系统与权限

### 4.1 角色与权限模型

系统采用基于角色的访问控制（RBAC），共三类角色：

| 角色 | 标识 | 核心权限 |
|------|------|----------|
| 管理员 | admin | 系统管理：用户管理、审计日志、全局会诊、系统配置（不参与临床诊疗与报告审核） |
| 医生 | doctor | 患者管理、虚拟会诊、会诊报告（含提交审核）、我的工作空间 |
| 审核员 | reviewer | 审核工作台、会诊报告（只读 + 审核确认）、审核记录 |

> 🔒 权限说明：三类角色导航与工作空间完全隔离——管理员仅维护系统信息；医生负责临床诊疗全流程并提交报告审核；审核员专注审核工作台、报告审核与审核记录，不参与患者管理与会诊发起。会诊报告页的"提交审核"按钮仅医生可见，"审核确认"按钮仅审核员可见。审核员通过审核队列（`ReviewQueue`）跨用户读取待审核报告，审核结果通过 `GlobalConsultationIndex.update_report_status()` 回写医生空间。

权限定义集中在 `Role.can_review()`，`User.can_review()` 委托给角色，便于统一维护。

### 4.2 密码安全

- 密码使用 **PBKDF2-HMAC-SHA256** 算法 + 随机 salt 哈希存储（迭代 10 万次），永不明文落盘
- 验证采用常量时间比较（`secrets.compare_digest`），防止计时攻击
- 用户数据持久化在 `data/users/users.json`，原子写入（临时文件 + 重命名）

### 4.3 用户数据空间

每个用户拥有独立的数据空间，实现数据隔离：

```
data/userdata/<user_id>/
├── consultations/      # 该用户的会诊报告（JSON）
├── patients/           # 该用户保存的患者数据（JSON）
└── images/             # 该用户上传的医学影像图片（DICOM/JPG/PNG/BMP 等）
```

- 医生只能看到自己空间的会诊、患者与影像
- 管理员可通过"全局会诊"查看所有用户的会诊记录
- 审核员通过审核队列跨用户读取待审核报告，审核结果回写医生空间（不复制报告副本）
- 审核队列统一持久化在 `data/review_queue/queue.json`（原子写入，每行记录含提交/审核状态）
- 审计日志统一记录在 `data/audit/audit.log`（每行一条 JSON）

### 4.4 修改密码

在顶部头部栏点击"修改密码"：
- 需输入原密码、新密码、确认新密码
- 新密码不少于 6 位
- 修改成功后写入审计日志（`CHANGE_PASSWORD`）

### 4.5 退出登录

点击"退出登录"可返回登录窗口，便于切换用户。退出操作写入审计日志（`LOGOUT`）。您的个人空间数据在重新登录后依然保留。

## 5. 医生工作台功能详解

### 5.1 患者列表

启动后左侧"示例患者列表"显示所有内置示例患者。点击任一患者：
- 系统从 HIS/EMR/LIS/PACS 适配器重新整合病历
- 患者全景视图、会诊视图、报告视图同步更新
- 状态栏显示"已切换患者: xxx"

### 5.2 从 JSON 加载患者

      "age": 60,
      "department": "心内科",
      "attending_doctor": "李医生",
      "admission_date": "2026-07-31",
      "chief_complaint": "胸痛2小时",
      "present_illness": "...",
      "past_history": "...",
      "physical_exam": "...",
      "lab_results": [
        {"item_name": "肌钙蛋白", "value": "2.8", "unit": "ng/mL",

### 5.3 智能推荐专家

"智能推荐"功能基于患者症状/病史/用药/影像，自动匹配适合参与的专科：

- 呼吸道症状（咳嗽、咳痰、呼吸困难、胸痛、气促）→ 呼吸内科
- 心血管症状（胸痛、心悸、水肿、高血压）→ 心内科
- 神经症状（头痛、头晕、意识障碍、肢体无力）→ 神经内科
- 内分泌线索（多尿、多饮、糖尿病、血糖异常）→ 内分泌科
- 已有影像检查 → 影像科
- 已有用药 → 药学科

### 5.4 医学知识图谱

点击"查看医学知识图谱"打开对话框：

- **症状查询**：输入多个症状（逗号分隔），返回可能的疾病及置信度
  - 示例：`咳嗽,呼吸困难` → 返回 COPD、肺炎、心力衰竭等
- **疾病查询**：输入疾病名称，返回典型症状与推荐检查
  - 示例：`慢性阻塞性肺疾病` → 症状：呼吸困难/咳嗽/咳痰/胸痛；检查：肺功能/胸部CT/胸片

### 5.5 会诊报告结构

**上传影像**：
1. 在"患者管理"页面选中患者
2. 在右侧"医学影像图片"卡片点击 **"上传影像图片"**
3. 选择本地影像文件，系统自动复制到当前用户空间并记录元数据
4. 上传成功后图片以缩略图形式显示在列表中，并写入审计日志（`UPLOAD_MEDICAL_IMAGE`）

## 6. 管理员后台

仅**管理员**角色可见"⚙️ 系统管理"导航项。管理员仅负责系统信息维护，不参与临床诊疗与会诊报告审核。管理员后台依据《后端管理平台完整功能》设计书实现，包含 **10 大管理模块**（标签页），所有操作均写入审计日志。

### 6.1 工作台概览

- 业务指标卡片：用户总数、AI 智能体数、数据源适配器数、全局会诊数

- 最近操作动态：展示最新 10 条审计日志

### 6.2 用户与权限管理

- **用户列表**：展示所有用户的 ID、用户名、姓名、角色、科室、职称、启用状态、最后登录时间
- **新建用户**：填写用户名、姓名、角色、科室、职称、密码（不少于 6 位）
- **编辑用户**：修改姓名、角色、科室、职称（用户名与密码不可在此修改）
- **重置密码**：为用户设置新密码
- **启用/停用**：临时停用账户（停用后无法登录）

## 7. 典型工作流

### 7.1 工作流一：呼吸系统病例 MDT 会诊

> 患者：李建国，男，65 岁，呼吸内科。反复咳嗽咳痰 2 月，加重伴呼吸困难 1 周。

## 8. 与医院现有系统对接

### 8.1 适配器架构

系统通过适配器（Adapter）模式对接医院信息系统：

```
医院信息系统      适配器           系统内统一数据模型
─────────────    ───────────     ──────────────────
HIS  ──────→  HISAdapter  ──→  Patient.name/age/...
EMR  ──────→  EMRAdapter  ──→  Patient.chief_complaint/...
LIS  ──────→  LISAdapter  ──→  Patient.lab_results
PACS ──────→  PACSAdapter ──→  Patient.imaging_reports
```

### 8.2 接入真实医院系统

替换 Mock 适配器为真实适配器：

```python
from src.adapters.his_adapter import HISAdapter
from src.adapters.emr_adapter import EMRAdapter
from src.adapters.lis_adapter import LISAdapter
from src.adapters.pacs_adapter import PACSAdapter
from src.core.medical_record import MedicalRecordIntegrator

integrator = MedicalRecordIntegrator()
integrator.add_adapter(HISAdapter({"endpoint": "http://his.hospital.com/api"}))
integrator.add_adapter(EMRAdapter({"endpoint": "http://emr.hospital.com/api"}))
integrator.add_adapter(LISAdapter({"endpoint": "http://lis.hospital.com/api"}))
integrator.add_adapter(PACSAdapter({"endpoint": "http://pacs.hospital.com/api"}))

patient = integrator.integrate("P001")
```

### 8.3 自定义适配器开发

继承 `HospitalAdapter` 实现三个方法即可：

```python
from src.adapters.base import HospitalAdapter

class CustomHISAdapter(HospitalAdapter):
    def __init__(self):
        super().__init__("HIS", config={})
    
    def connect(self) -> bool:
        # 实现：连接真实 HIS（HL7/FHIR/REST API）
        return True
    
    def fetch_patient_data(self, patient_id: str) -> dict:
        # 实现：调用 HIS API 返回标准化字段
        return {
            "name": "...",
            "gender": "...",
            "age": 60,
            # ...
        }
    
    def is_available(self) -> bool:
        return True
```

### 8.4 多适配器合并行为

系统支持同一系统配置多个适配器（例如同时接入主备 HIS），数据合并规则：
- **标量字段**（name、age 等）：先到先得，后到不覆盖非空字段
- **列表字段**（lab_results、medications 等）：合并去重
- **同名适配器**：自动合并，不会互相覆盖

## 10. 测试体系（test.xlsx 数据驱动测试）

### 10.1 设计理念

为提升测试的可维护性与可读性，系统采用**数据驱动测试**方案：将测试项与测试用例从代码中剥离，单独存储在 `tests/test.xlsx` 文件中，测试代码直接读取该文件执行。

优势：
- **测试与数据分离**：非开发人员也能通过编辑 Excel 增补用例，无需改代码
- **用例一目了然**：每条用例的输入、期望、断言类型在表格中清晰可见
- **可扩展**：新增测试项只需在 xlsx 增加一行并实现对应 operation

### 10.2 文件结构

`tests/test.xlsx` 包含两个工作表：

- **test_cases**：测试用例数据，列定义如下：

| 列 | 说明 |
|----|------|
| 用例ID | 唯一编号，如 TC-P001 |

### 10.3 断言类型

| 类型 | 含义 |
|------|------|
| `truthy` / `falsy` | 实际值为真 / 为假 |
| `not_null` | 实际值不为 None |
| `equals` | 实际值（字符串化后）等于期望 |
| `contains` | 实际值包含期望字符串 |
| `count` | 实际值长度等于期望整数 |
| `json_has_key` / `json_has_no_key` | dict 包含 / 不包含期望键 |
| `json_field_equals` | 期望格式 `字段=值`，dict 字段等于值 |
| `throws` / `throws_contains` | 操作应抛异常 / 异常消息包含期望字符串 |

## 11. 常见问题排查（FAQ）

### Q1：启动后窗口为空白，看不到数据？

**原因**：示例数据加载失败，可能是 `data/sample_cases.json` 缺失或损坏。  
**解决**：
- 检查程序目录下 `_internal/data/sample_cases.json` 是否存在
- 重新解压发布包

### Q2：会诊执行时报错"没有可用的智能体参与会诊"？

**原因**：未选择任何专家，或选择的专家 ID 无效。  
**解决**：
- 点击"智能推荐"或"全选"重新选择专家
- 至少勾选一位专家

### Q3：审核报告后状态未变化？

**原因**：旧版本直接修改本地状态，未走引擎流程。  
**解决**：本版本（V2.2）已修复，确保点击"审核确认"并填写审核人姓名（仅审核员可见该按钮）。

### Q4：从 JSON 加载患者时报"JSON 解析失败"？

**原因**：JSON 文件格式不正确或编码不是 UTF-8。  
**解决**：
- 使用文本编辑器验证 JSON 格式（如 VS Code、Notepad++）
- 保存为 UTF-8 编码（无 BOM）
- 参考 `data/sample_cases.json` 模板

### Q5：打包后的程序双击无反应？

**原因**：可能缺少依赖 DLL，或被杀毒软件拦截。  
**解决**：
- 在 `医院虚拟会诊系统.exe` 同目录下打开命令行，运行 `医院虚拟会诊系统.exe`，查看错误信息
- 将发布目录加入杀毒软件白名单
- 重新打包：`python scripts/build_exe.py`

### Q6：jieba 词典加载慢或报错？

**原因**：首次运行 jieba 需要构建词典缓存。  
**解决**：首次启动会自动生成缓存（位于 `%TEMP%\jieba.cache`），后续启动会变快。

### Q7：如何扩展医学知识图谱？

修改 `src/core/knowledge_graph.py` 的 `build_default_knowledge_graph()` 函数，或加载外部 JSON：

```python
kg = MedicalKnowledgeGraph()
kg.load_from_file("custom_kg.json")
```

JSON 格式见 `MedicalKnowledgeGraph.to_dict()` 输出。

### Q8：如何接入 LLM 增强推理？

当前智能体基于规则，可通过继承 `SpecialistAgent` 接入大语言模型：

```python
from src.core.agent import SpecialistAgent, AgentOpinion

class LLMCardiologyAgent(SpecialistAgent):
    def analyze(self, patient):
        prompt = self._build_prompt(patient)
        # 调用 LLM API（如 DeepSeek/通义千问）
        response = call_llm(prompt)
        return self._parse_response(response)
```

## 12. 安全与合规说明

### 12.1 数据安全

- **本地化处理**：患者数据默认在本地处理，不上传外部服务器
- **数据脱敏**：通过 `Patient.to_public_dict()` 可导出脱敏后的患者信息（屏蔽身份证号、电话）
- **真实环境部署**：需遵循《信息安全技术 个人信息安全规范》、《个人信息保护法》及医疗机构等保三级要求
- **数据传输**：与医院系统对接时建议使用 HTTPS/TLS 加密通道

### 12.2 访问控制

- **基于角色的访问控制（RBAC）**：V2.2 已内置管理员/医生/审核员三类角色与权限模型；管理员仅维护系统信息，不参与临床诊疗与报告审核
- **审核流程**：报告审核需要填写审核人姓名，操作记录到引擎状态机与审计日志
- **登录安全**：密码 PBKDF2 哈希存储，登录失败锁定，登录成功/失败均审计
- **数据隔离**：用户个人空间隔离，管理员可全局查看
- **审计追溯**：会诊流程日志通过 `MedicalRecordIntegrator.get_integration_log()` 与 `ModeratorAgent.get_discussion_log()` 可查询；全局审计日志见 `data/audit/audit.log`

### 12.3 临床合规

- **辅助决策定位**：本系统不替代执业医师的诊断与治疗决策
- **人工审核**：所有 AI 生成的会诊意见均需经主治医师审核确认后方可执行
- **不确定性声明**：系统在诊断置信度不足时主动提示不确定性，避免过度自信

### 12.4 已知限制

1. 当前智能体基于规则与关键词匹配，**未接入大语言模型**，对复杂病例推理能力有限
2. 医学知识图谱覆盖 7 种常见疾病，**未覆盖罕见病**
3. 不支持影像图像的像素级 AI 分析，仅解读文本报告；患者关联的医学影像图片仅用于浏览与归档
4. 多线程访问会诊引擎时未加锁，**不建议在多进程并发场景部署**
